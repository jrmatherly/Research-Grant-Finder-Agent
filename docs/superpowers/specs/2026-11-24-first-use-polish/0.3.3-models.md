## B. Text models only

The owner asked whether the list holds only the models his key can use. It does not, as far as any provider documents:
- Anthropic says only that the list "can be used to determine which models are available for use in the API". A `deprecated` model "remains callable for organizations with existing access, but is ... closed to new adopters" (docs: https://platform.claude.com/docs/en/api/models/list).
- OpenAI's reference says nothing on filtering (docs: https://developers.openai.com/api/reference/resources/models/methods/list).
- Google says a 200 from `models.list` does not confirm inference works (earlier pass). His free-tier key could call `gemini-4-argon`, which has no free tier, and got a 503 rather than a refusal (the owner's report).

Fields per provider:
- **Anthropic** `GET /v1/models` (docs, list page above): `id, type, display_name, created_at, capabilities{batch, citations, code_execution, context_management, effort, image_input, pdf_input, server_tools, structured_outputs, thinking}, lifecycle (active|deprecated|retired), deprecated_at, retires_at, line, max_input_tokens, max_tokens`. No output-modality field, and none is needed: "All current models support text and image input, text output" (docs: https://platform.claude.com/docs/en/about-claude/models/overview). Use `lifecycle`: keep `active`. The default list holds active and deprecated and leaves out retired.
- **OpenAI** `GET /v1/models` (docs): `id, object, created, owned_by, shutdown_date`. No capability, modality or type field. The all-models page lists image, realtime/audio, transcription, TTS, embedding and moderation models (docs: https://developers.openai.com/api/docs/models/all). Some text models do not work on the route Grant Matcher calls. `gpt-5.5-pro` supports only `v1/responses` and `v1/batch`, and Chat Completions is "Not supported" (docs: https://developers.openai.com/api/docs/models/gpt-5.5-pro). `gpt-6.2-astra` supports both (docs: https://developers.openai.com/api/docs/models/gpt-6.2-astra).
- **Gemini** `GET /v1beta/models` (docs: https://aistudio.google.com/api-reference/models): `name, baseModelId, version, displayName, description, inputTokenLimit, outputTokenLimit, supportedGenerationMethods, temperature, maxTemperature, topP, topK, thinking`. No output-modality or Interactions field. The examples given for `supportedGenerationMethods` are `generateMessage` and `generateContent`. TTS and image models still list `generateContent` (the owner saw `gemini-2.5-flash-preview-tts` after today's filter). So `generateContent` stays the best available field. It drops embeddings, which list `embedContent`. Gemma writes text: the Interactions page names Gemma 4 31B IT and 26B MoE IT as supported (earlier pass, section 6). So Gemma stays in the list.
- **compatible**: no filter. A local server lists what it serves. An embedding model there (such as `nomic-embed-text`) stays listed. Test connection says so if it is picked.

**Rule.** Where no field exists, deny by name, which is the least fragile option. A new text model shows up without a change. A new kind of non-text model shows up until a name is added, and Test connection then explains the failure. The alternative is to allow only known names, which hides every new text model until someone updates the pattern.

The pattern was run over the official id lists (run, `scratchpad/deny.py`):
- **OpenAI.** Drops all image, realtime, live, audio, transcribe, TTS, whisper, embedding and moderation ids. It also drops the `-pro`, `codex`, `deep-research` and `computer-use` ids, which are Responses-only (per the gpt-5.5-pro page; the others are a guess from their names, and most are deprecated). It keeps these deprecated or doubtful ids: `gpt-daybreak-red-latest`, `gpt-daybreak-blue-latest`, `gpt-4o-search-preview`, `gpt-4o-mini-search-preview`, `o1-preview`, `gpt-6-cyber`, `gpt-5.6-cyber` (access gated per the page), `gpt-oss-120b`, `gpt-oss-20b` (open-weight, probably absent from the API list; guess). It wrongly drops nothing else that I can find among the current text ids.
- **Gemini.** Keeps `gemini-4-carbon, -neon, -hydrogen, -argon, gemini-3.8-flash, 3.6-flash, 3.5-flash-lite, 3.1-flash-lite, 3-flash-preview, 3.1-pro-preview, 2.5-flash, 2.5-flash-lite, 2.5-pro`. It drops every live, TTS, image, transcribe, translate, omni, genie, lyria, imagen, deep-research, antigravity, embedding and robotics id. It also drops `gemini-decision-1`, whose output the models page does not state; dropping it may be wrong (guess).

Proposed code, prototyped (llm.py):

```python
# shortcut: a pattern on the name, since only Anthropic's list says what a model does. Add a family when a provider lists a new kind that cannot write text.
NOT_TEXT = {"openai": r"embedding|moderation|tts|whisper|transcribe|realtime|audio|image|dall-e|sora|live|translate|computer-use|codex|deep-research|-pro\b|babbage|davinci", "gemini": r"tts|image|embedding|live|audio|transcribe|translate|omni|genie|lyria|imagen|veo|robotics|computer-use|deep-research|antigravity|decision|nano-banana|aqa"}

def list_models(provider: Provider, base_url: str, key: str | None, workspace: str = "") -> list[str]:
    base = base_url.rstrip("/")
    try:
        if provider.wire == "anthropic":
            # Anthropic's page: a deprecated model stays callable only for an organization that already used it.
            found = [m["id"] for m in _send(f"{base}/models?limit=1000", {**_bearer(key), **_workspace(workspace), "anthropic-version": ANTHROPIC_VERSION}, None, key, 30)["data"] if m.get("lifecycle", "active") == "active"]
        elif provider.wire == "gemini":
            found = [m["name"].removeprefix("models/") for m in _send(f"{base}/models?pageSize=1000", {"x-goog-api-key": key} if key else {}, None, key, 30)["models"] if "generateContent" in m.get("supportedGenerationMethods", [])]
        else:
            # Newest first, as Anthropic lists its models. OpenAI's page names no order.
            found = [m["id"] for m in sorted(_send(f"{base}/models", _bearer(key), None, key, 30)["data"], key=lambda m: -_count(m.get("created")))]
    except (KeyError, TypeError, AttributeError) as exc:
        raise ModelError(f"The model list from {host_of(base_url)} was not in the form Grant Matcher reads: {exc!r}") from None
    # A server behind the compatible provider lists only what it serves.
    skip = NOT_TEXT.get(provider.name)
    return [name for name in found if not (skip and re.search(skip, name))]
```

I filtered on the client because `lifecycle` as a query array (`?lifecycle=active`) is documented, but I did not check its wire form with a live call.

## D. Reading the test result

Today (repo llm.py:117): 401/403 count as auth. 402, or a 429 whose type, code, status or details.error_code matches `quota|credit|spend|usage_limit`, counts as quota. Any other 429 counts as rate. 500/503/529 count as overload. Everything else is other. The message is `f"{host} answered {status}: {message}"` (llm.py:129), and a Claude workspace error appends `WORKSPACE_HINT`.

Documented codes:
- **Anthropic** (docs: https://platform.claude.com/docs/en/api/errors ; rate-limits page):
  - 400 `invalid_request_error`, which also covers a spend limit you set ("You have reached your specified API usage limits").
  - 401 `authentication_error`.
  - 402 `billing_error`.
  - 403 `permission_error` ("Your API key does not have permission to use the specified resource").
  - 404 `not_found_error`.
  - 429 `rate_limit_error`. A tier spend cap carries `details.error_code` `enforced_spend_limit_reached` and no `retry-after`. A ramp limit carries `ramp_limit_exceeded`.
  - 500 `api_error`.
  - 529 `overloaded_error` ("high traffic across all users").
  - A model a key cannot use is not named. The page lists no plan-gated model code.
- **OpenAI** (docs: https://developers.openai.com/api/docs/guides/error-codes):
  - 401 for an invalid key.
  - 403 for an unsupported region.
  - 429 for a rate limit, and with `slow_down`, `credit_balance_exhausted`, `organization_spend_limit_exceeded`, `project_spend_limit_exceeded` or `organization_usage_limit_exceeded`. `error.type` can still be `insufficient_quota`.
  - 500.
  - 503 `server_is_overloaded`.
  - No `model_not_found` or 404 entry. A 404 for a model the key cannot use is a guess.
- **Gemini** (docs: https://aistudio.google.com/docs/api-errors). The body is `{"error": {"code": "<name>", "message": ...}}`.
  - 400 `invalid_request` or `failed_precondition` ("disabled billing").
  - 401 `authentication`.
  - 402 `payment_required`.
  - 403 `permission_denied` ("project is restricted or requires verification or billing changes").
  - 404 `model_not_found`.
  - 429 `rate_limit_exceeded`, `quota_exceeded` ("daily quota") or `too_many_requests`.
  - 503 `service_unavailable`.
  - The page does not cover free-tier model access or a quota of zero. Forum reports (earlier pass, third party) show an older shape with `"status": "RESOURCE_EXHAUSTED"` and "limit: 0". Today's regex classes that as rate and waits and retries it. That is a guess about what his key gets for argon on a quiet day.

## E. The long dim

Today (repo llm.py:131-139 and 71):
- One request is up to 2 tries. A retry happens only on 429, 503 or 529 that is not quota, after `min(Retry-After or 2, 30)` seconds.
- Each try has `timeout=600`. urllib applies that to each socket operation (connect, each read), not to the whole request.
- The worst case is about 600 + 30 + 600 seconds, and a reply that trickles in can run longer. A 503 that comes back at once costs two round trips plus 2 s.
- How long Google held each 503 for the owner was not measured. The dim was most likely Google answering slowly, twice (guess).
- Meanwhile the callback runs before the rerun (`_act`, apply_page.py:36-53). The page shows Streamlit's running state with the old elements greyed. The page draws no message of its own (repo; the greying is how Streamlit behaves, not observed here).
